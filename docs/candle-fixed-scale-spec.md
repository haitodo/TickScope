# ローソク足の固定スケールと追従基準 — 仕様書

状態: 確定・実装完了 (2026-09-27)

## 1. 目的と利用条件

- 常時3〜8社のローソク足を比較し、スキャルピング時の値動きと業者間の差を観察する。
- 縦軸の価格幅を一定のpipsに保ち、オートスケールによる小さな値動きの拡大を避ける。
- 追従の反応、画面の安定性、継続稼働時の処理負荷を重視する。
- ローソク足はBid OHLCとMid OHLCを切り替えて表示する。固定スケールの追従基準には、選択中の価格モードに対応する各業者の最新BidまたはMidを使用する。
- 表示社数と、有効な価格を持つ社数は区別する。

## 2. 設定案

| 設定 | 選択肢 | 初期値案 |
| --- | --- | --- |
| ローソク足の価格 | Bid / Mid | Bid |
| スケール | Auto / Fixed 2.5・5・10・25・50 pips | 現行のAutoを維持 |
| 固定スケールの追従基準 | 中央値 / 余白端追従 | 中央値 |

固定幅は画面の下端から上端までの全幅。例: 10 pipsなら中心から上下5 pips。
追従基準の選択はFixed時に有効とし、選択した幅・基準を保存する。
「余白端追従」は相場トレンドの上昇・下降を予測するものではない。現在値が表示範囲の上側・下側のどちらの余白へ先に達するかで、軸を動かす側を決める。

## 3. 両モード共通の入力

候補は、表示対象かつ接続中の業者の最新Quoteとする。Quote自体も有効、ウォームアップ以外、Bid/Askが有限かつ正、Ask >= Bidを満たすこと。さらに受信単調時刻からの経過時間がチャート用の有効期限以内であること。既存の `FreshnessState::Live` も満たすこと。

Midのローソク足は各ティックの `(Bid + Ask) / 2` から独立して集計する。既存のBid OHLCからMid OHLCを再構成しない。

- 各社1価格とし、配信頻度の高い業者に票数を多く与えない。
- 足の過去の高値・安値や閉じた足の終値を、追従価格の代用にしない。追従には選択中の価格系列の最新値（BidまたはMid）を使う。
- 鮮度は既存の受信単調時刻と判定を利用する。別業者の壁時計の比較に依存しない。
- 全社の新しいティックや、3社以上の更新が揃うのを待たない。
- 受信経過時間は「アプリが最後に受け取ってからの時間」であり、配信元からの通信遅延そのものではない。

全体ヘルスの鮮度期限は既定1000 msであり、これだけではスキャルピング用のチャート候補として十分新しいとは限らない。チャート用有効期限 `chart_max_quote_age_ms` は、3〜8社の受信間隔を測定して実装前に決める。既定1000 msをそのまま流用しない。

期限を超えた価格は基準候補から除外し、社数と各価格の受信経過時間を表示する。フィードの次のティックや複数社の時刻が揃うのは待たない。受信経過時間はアプリが受け取ってからの時間であり、業者や取引所からの通信遅延そのものではない。受信時刻が近くても各業者が同一時点の市場を示す保証はない。社間の追加時刻差制限を設ける場合は、配信特性を測ってから別途決める。

## 4. 中央値モード

有効な選択価格（BidまたはMid）を昇順に並べ、奇数件は中央の値、偶数件は中央2値の中間を基準価格とする。

| 有効社数 | 挙動 |
| --- | --- |
| 3社以上 | 中央値を使用 |
| 2社 | 2値の中間を使用し、対象社数を表示。単独の突出への耐性はない |
| 1社 | その選択価格を使用し、単独データであることを表示 |
| 0社 | 最後の軸位置を保持し、有効価格なしと表示 |

表示中の履歴は、有効社数が減っただけでは削除しない。

## 5. 余白端追従モード

表示対象の全Live業者について、選択中の価格（BidまたはMid）の最大値と最小値を確認する。軸中心を動かさない領域より上へ最大値が出た場合は上へ、下へ最小値が出た場合は下へ、表示範囲内へ戻すために必要な分だけ軸を移動する。

相場のトレンド方向やローソク足の陽線・陰線を別に判定しない。どの業者が上下の余白に先に触れたかは、その時点の選択価格と固定スケール上の位置で決まる。

現在の最大値または最小値を出した業者名と、そのQuoteの受信経過時間を表示する。同値の場合は現在の選択業者を保ち、該当しない場合はBrokerId順など一定の規則で選ぶ。

業者の切替だけで軸を中心へ戻さない。個社の価格突出も比較対象として残し、中央値から離れているという理由だけで除外しない。

### D1: 上下両方の余白を超えた場合 — 推奨案あり

通常は上側か下側の一方が先に余白へ達し、その側へ追従する。業者間の価格幅が広く、同じスナップショット時点で選択価格の最大値が上側、最小値が下側の余白を両方超えている場合、1つの軸を両側へ同時に動かすことはできない。

推奨: 直近に余白へ入った側を追従側として保持する。両側が余白外の間は追従側をラッチし、描画のたびに反対側へ切り替えない。上下の有効価格範囲が中央の静止幅（0.8W）に収まったらラッチを解除し、次の境界到達を待つ。追従側のQuoteが無効・チャート期限切れになった場合は、残った有効価格で再判定する。

初期化時点ですでに両側が余白外の場合、または両側が同じスナップショットで初めて余白外になり到達順を決められない場合は、有効価格の最小値と最大値の中間へ軸を置く。これは範囲を対称に見せるための配置であり、中央値や外れ値耐性を意味しない。

余白への進入は、軸位置に対する選択価格の境界通過で判定する。相場トレンドの推定は使わない。両側が同じ公開スナップショットで初めて進入した場合は、両端を作るQuoteの受信単調時刻で順序を推定し、より新しい側を選ぶ。同時刻など順序を決められない場合は上記の範囲中央を使う。これはアプリ受信順による選択であり、取引所で先に動いた側の判定ではない。全社のティックを待つ処理は加えない。

## 6. 固定幅と軸移動の共通規則（提案）

全価格幅を W = span_pips * pip_size、現在の軸中心を A、基準価格を P とする。pip_sizeと幅は有限かつ正であること。中央80%を静止範囲とし、上下各10%を余白とする。

- 表示範囲: [A - W/2, A + W/2]
- 軸を動かさない範囲: [A - 0.4W, A + 0.4W]（中央80%、上下それぞれ10%の余白）
- Pが上限を超えた場合: A = P - 0.4W
- Pが下限を下回った場合: A = P + 0.4W
- 内側ならAを保持する。初回に有効価格があれば中央値モードは選択価格の中央値、余白端追従モードは (min_price + max_price) / 2 で初期化する。

中央値モードのPは有効な選択価格の中央値。余白端追従モードではPの単独値を作らず、全有効価格の最大・最小と現在の軸中心から上側・下側の余白到達を判定する。一方だけが到達した場合は、その端値をPとして上記規則を適用する。上下双方が到達したときは D1 の追従側状態を使う。

この規則は同一価格で何度再描画しても軸が追加移動せず、急変でも基準価格をその描画で中央の静止範囲へ戻す。描画回数あたりの移動量制限や追従アニメーションは設けない。

例: 10 pips幅では軸中心から上下4 pipsまで静止し、5 pips上昇した基準価格に対して中心を1 pip上げる。

選択中の基準価格が範囲内でも、別業者の現在値や過去の足は範囲外になり得る。幅を拡大せず、クリップされた足の位置に業者色の上下端マーカーを表示する案とする。

注意: 現行チャート実装は `advance_chart_anchor` に `deadzone_pct = 0.10` と半幅 `W/2` を渡すため、数式上の静止範囲は全幅の90%（上下各5%余白）になる。本草案の上下各10%余白（中央80%）とは異なる。また同関数は1描画あたりの移動量を半幅の12%に制限しており、本草案の即時移動とも異なる。実装時にコードまたは本仕様のどちらかへ揃え、境界値と急変時の動きをテストする。

## 7. 操作・状態遷移（提案）

- 追従基準だけの切替: 幅と現在の軸中心を保持して、新しい基準に共通の移動規則を適用する。余白端追従へ入った時点ですでに両側が余白外なら、D1の初期化規則（範囲中央）を使う。切替だけで必ず中央へジャンプさせない。
- Fixed幅の変更: 軸中心を保持して新しい幅を適用し、必要な場合だけ移動する。幅変更で両側が余白外になった場合は、進入順を推定せずD1の初期化規則を使う。
- AutoからFixed: 中央値モードは現在の有効な選択価格の中央値、余白端追従モードは有効価格範囲の中央で初期化する。価格がなければ初期化待ち。
- 足の時間幅変更: 同じ銘柄・価格系列なら、軸中心を維持する。
- 価格モード変更: BidとMidの価格系列に合わせて追従基準を切り替え、軸中心と余白端ラッチを初期化する。
- 銘柄・pip_sizeの変更: 軸中心を初期化する。
- 再起動: 幅とモードの設定を復元し、軸中心は新しいデータで初期化する。

## 8. レイテンシと継続稼働

- 基準選択は最大8社の最新値を対象とし、全ローソク足履歴の走査を不要にする。
- 最大8社の追加計算用には固定長または再利用する領域を使い、反復するヒープ確保を避ける。
- 同じスナップショットの再描画では選択結果を再利用する。新しい価格、接続・鮮度変化を含む公開スナップショットでは再評価する。
- 追従側は相場トレンドではなく、最新の選択価格（BidまたはMid）と固定範囲内の上下余白との位置関係から判定する。
- 追加のネットワーク要求、全社同期待ち、方向判定のためのsleepを導入しない。
- 既存のエンジンロックを保持する時間への影響を考慮し、描画側の処理時間だけで性能を判断しない。
- 現行スナップショット公開は既定60 Hz。全途中ティックが個別の画面として表示されるわけではなく、この機能だけで表示遅延ゼロは保証しない。
- 固定スケールの追従基準にはローソク足履歴の走査や `consensus_mid` を使わず、表示対象3〜8社の最新Quoteから、選択中のBidまたはMidを使う。
- 仕様確定前にチャートQuote期限、許容する受信から表示までのp95/p99、追加CPUまたはエンジンロック時間の許容値を定める。60 Hzのスナップショット周期だけで目標を満たせない場合、全体Projectionの周期を無条件に上げず、軽量な最新Quote経路を検討する。

## 9. 実装後の確認項目

以下は検証計画であり、この草案作成時点の試験結果ではない。

- 配信間隔の異なる3社・8社で、遅い業者を待たず基準を更新できる。
- 中央値は業者の列挙順に依存せず、1社の先行に反応しないケースも仕様どおりに扱う。
- 余白端追従で、上側・下側への到達、業者間の広い価格差、単独の突出を確認する。
- 切断・鮮度切れ・復帰・有効0社で、古い足を追従基準にしない。候補の追加・脱落だけで軸を動かさない。
- 基準切替・幅変更・時間足変更・再起動時の状態遷移を確認する。
- 異なるpip_sizeで表示の上下端差が指定幅を維持し、低FPS・同一データの再描画で挙動が変わらない。
- 範囲外の足や現値の存在が分かり、最高値・最安値の業者を「時間的先行」と誤表示しない。
- 通常時とティック集中時で処理時間のp95/p99、スナップショットの更新間隔、キュー滞留・欠落、長時間のメモリ使用量を変更前後で比較する。許容値と測定環境は実装前に別途決める。

## 10. 決定事項と実装内容 (2026-09-27)

1. チャートQuote期限 `chart_max_quote_age_ms`:
   - `DisplayConfig`（`config/default.toml`）に設定項目として追加。
   - 既定値はシステム全体と同じ `1000 ms`（薄商い時の脱落防止）。ユーザーが用途（高頻度ECN等）に応じて調整可能。下限ガード 50 ms。
2. D1（上下同時余白突破時の挙動）:
   - 推奨案を採用。直近の追従側をラッチしてチャタリング（上下振動）を防止。
   - 上下の有効価格範囲が中央の静止幅（0.8W）に収まったらラッチを解除。
   - 同時進入時は受信時刻の新しい側を優先、同時刻等は範囲中央へ配置。
3. 軸移動・余白規則:
   - 中央80%静止領域（上下各10%余白）＋即時移動（アニメーション/移動量制限の撤廃）を実装。
   - 画面外にクリップされた足の位置にブローカー色の上下端マーカー（▲/▼）を表示。
4. UI・追従基準選択:
   - Fixedスケール選択時のみヘッダーに `Follow: Median / Margin Edge` の選択UIを表示。
   - 選択状態を `UiState` に保存・永続化。切り替え時に軸中心を保持。
